# v1.4.0 — Backlog técnico, carga de config sin credenciales y conversor de `fetch` corregido

**Fecha:** 2026-10-01
**Tipo:** Minor
**Versión anterior:** v1.3.0

---

## 1. Solicitud

Dos orígenes, un único tag.

**Backlog técnico.** Los días sin tareas asignadas, cada desarrollador tiene que
identificar a mano trabajo que justifique la jornada. Se pidió algo que detecte
deuda técnica real en los repos y la proponga como tareas, reutilizable por
todo el equipo y sin depender de pedirle un análisis a nadie cada día.

**Revisión de `fetch`.** Un aviso del editor (*"Inefficient string
concatenation in call to WriteString"*) en `storage_text.go` llevó a revisar el
conversor de Confluence a texto, que no tenía tests. Se pidió corregir, en el
mismo cambio, los bugs que aparecieran. Entró a `main` en el PR #5
(`refactor/config-load-local`).

---

## 2. Motivación

| Problema | Daño real |
|---|---|
| No había forma de encontrar deuda técnica sin revisar el repo a mano | Cada día sin tareas, cada desarrollador repetía el mismo análisis, o registraba horas sin un trabajo concreto que las respaldara |
| `config.Load()` exige credenciales de Atlassian | Un comando que solo lee repos locales no podía usarse antes de `gtt init`, ni por alguien sin token |
| Un `config.yaml` con error de sintaxis se ignoraba en silencio | El mensaje era "configuración incompleta. Corre: gtt init", que lleva a rehacer la configuración en vez de corregir una línea |
| `StorageToText` perdía o deformaba contenido | `gtt fetch` exportaba `.txt` con texto pegado (`Rama:main`), entidades crudas (`caf&eacute;`), tareas completadas como pendientes, paneles sin encabezado y documentos cortados sin aviso |

## 3. Diseño técnico

### 3.1 `gtt backlog scan`

```
gtt backlog scan [-p proyecto] [-r backend|frontend] [--path ruta] [--since 90d]
                 [-l 10] [-o [ruta]] [--json] [--deps]
```

Paquete nuevo `internal/backlog` (lógica pura + git de solo lectura) y
`cmd/backlog.go` (flags, config, salida). Solo lee el historial de git y los
archivos versionados: no modifica el repo, no usa la red salvo con `--deps` y no
necesita credenciales (`config.LoadLocal`, ver 3.3).

| Detector | Regla | Severidad |
|---|---|---|
| `hotspot` | ≥ `min_commits` (10) commits en el período | Alta si además supera `max_lines`; media si no |
| `sin-test` | El nombre de la clase no aparece en ningún archivo de test. Requiere `class_globs` | Baja; alta si además es hotspot |
| `marcador` | `TODO`, `FIXME`, `HACK` en mayúsculas y como palabra completa | Media con FIXME/HACK; baja con solo TODO |
| `archivo-grande` | > `max_lines` (800) y **no** es hotspot | Baja; media desde 3× el umbral |
| `dependencia` | `composer audit --locked`, solo con `--deps` | Alta |

**Hotspot por frecuencia de cambio, no por palabras clave.** La primera versión
contaba commits cuyo asunto decía "fix" o "corrección". Contra `operativo-api`
devolvió cero hotspots: solo 25 de 234 commits en 90 días usan esas palabras,
porque el equipo nombra los arreglos por el síntoma ("no queda persistente",
"pérdida de delegados"). La frecuencia de cambio es el predictor clásico de
dónde se concentran los defectos y no depende de cómo se redacten los commits.
`fix_keywords` quedó solo como evidencia ("4 de 18 commits parecen
correcciones").

**Tareas de un incremento.** El título propone "Extraer una responsabilidad de
X y cubrirla con tests", no "Refactorizar X". Una clase de 5.000 líneas no es
una tarea de 3 puntos, pero sí puede alimentar varias; por eso los puntos no
crecen con el tamaño del archivo. La primera versión decía "Dividir X (4952
líneas), 5 pts", que no era una estimación creíble.

**El tamaño solo no es urgencia.** Un archivo grande que nadie toca cuesta poco:
queda en baja. La primera corrida llenaba el top con seeders de datos de 8.000
líneas. Un hotspot grande ya lleva su tamaño en el título, así que no se repite
como `archivo-grande`.

**Defaults genéricos, específicos en config (P-001, P-008).** Las extensiones,
exclusiones (`vendor/`, `node_modules/`, migraciones, seeders, fixtures, lockfiles…)
y nombres de test por defecto son convenciones generales. Dónde viven las clases
y los tests de cada stack va en `config.yaml`, por proyecto y por repo:

```yaml
projects:
  mi-proyecto:
    backlog:
      backend:
        class_globs: ["app/Http/**/BusinessLogic/**/*.php"]
      frontend:
        class_globs: ["src/app/**/*.service.ts"]
        test_globs: ["**/*.spec.ts"]
```

`matchGlob` implementa `**` sobre `path.Match`, sin dependencias nuevas.

**Tests reconocidos por nombre.** Sin configurar nada, son test los archivos bajo
`tests_dir` y los que siguen `*.spec.*`, `*.test.*`, `*_test.*`, `test_*.py`,
`*Test.*`, `*Tests.*`. Antes, en un frontend Angular los `.spec.ts` se analizaban
como código y aparecían como "archivo grande". `test_globs` reemplaza ambos
criterios para stacks con otra convención.

**Clase esperada por archivo.** `PagoService.php` → `PagoService`;
`pago-detalle.service.ts` → `PagoDetalleService`; `pago_service.py` →
`PagoService`. Cubre PSR-4/Java/C#, Angular y Python. El índice de
identificadores de los tests se arma una sola vez: cada consulta es O(1).

**`XXX` no es marcador.** En datos se usa como relleno (`"CXXXXXX-TYT-XXX"`, un
código de moneda en un seeder) mucho más que como marcador; las dos coincidencias
reales en los repos del equipo eran falsos positivos.

**Un detector que falla no aborta el scan.** Queda en `omitidos` con el motivo
(sin `class_globs`, composer ausente, git con error): un reporte corto nunca se
confunde con un repo limpio. Solo es fatal no poder abrir el repo.

**IDs estables.** `sha1(tipo + "\x00" + archivo)[:10]`: el mismo hallazgo tiene el
mismo id entre ejecuciones y entre máquinas. Es la base para que una versión
posterior recuerde qué hallazgos ya se mostraron, se tomaron o se descartaron.

### 3.2 Varios repos, un archivo por repo y multiplataforma

**Todos los repos del proyecto por defecto.** Sin `-r`, se analizan el backend y
el frontend que tengan ruta configurada; `-r` elige uno. Pedir con `-r` un repo
sin ruta configurada es error. Antes se caía a la carpeta actual y se analizaba
otro repo con el nombre equivocado. Si falla un repo, el otro se analiza igual y
el error se informa al final.

**`-o` en lugar de `>`.** gtt escribe el JSON él mismo, en UTF-8, con permisos
0600 (en Windows hereda los permisos del perfil del usuario). En Windows
PowerShell 5.1, `>` guarda en UTF-16 y el archivo deja de ser JSON legible para
otras herramientas. Sin ruta, va a `~/.config/gtt/backlog/<proyecto>-<repo>.json`
(en Windows `%USERPROFILE%\.config\gtt\backlog\`), junto al `config.yaml`. Nunca
va a una carpeta sincronizada: el reporte contiene rutas y mensajes de commits
internos. Guarda todos los hallazgos; `--limit` solo recorta lo que se muestra.
Con varios repos, `-o` recibe una carpeta, y un `.json` es error.

**`--json` siempre devuelve una lista** (un reporte por repo), para que quien lo
consuma no dependa de cuántos repos se analizaron. `Report.Version` (1) se
incrementa si cambia la forma.

**Rutas según el sistema.** En pantalla, el separador del sistema (`app\Http\…`
en Windows). En el JSON, siempre `/`, como git: el id se calcula sobre la ruta y
tiene que coincidir entre un compañero en Linux y otro en Windows. La ayuda
muestra ejemplos en el formato del sistema donde corre (`C:\repos\mi-api` o
`~/repos/mi-api`). Los ejecutables se resuelven con `exec.LookPath` (P-005), que
encuentra `git.exe` y `composer.bat` en Windows, y se invocan sin shell
intermedio, así que no hay diferencias de comillas ni escapes entre PowerShell y
bash. `git log` corre con `core.quotePath=false` y `git grep` con `--null`, para
que las rutas con tildes o con `:` se lean bien.

### 3.3 `config.LoadLocal`

`Load()` queda como `LoadLocal()` + validación de credenciales. `LoadLocal()`
aplica la misma prioridad (env vars > `config.yaml`) sin exigir email, token y
URL. `configFromEnv`, `mergeMissing` y `HasAtlassianCredentials` salen del bloque
único anterior.

Cambio de comportamiento deliberado: un `config.yaml` inexistente sigue sin ser
error, pero uno que existe y no se puede leer o parsear ahora se reporta
(`<ruta> tiene un formato inválido: …`) en lugar de terminar en "configuración
incompleta. Corre: gtt init".

### 3.4 `StorageToText` (`gtt fetch`)

Antes de tocar nada se escribieron tests que fijan la salida exacta, byte a
byte, y pasaron con el código original. Después se reescribió la función
(230 líneas en una sola) como un `storageConverter` con un método por evento del
parser. El estado de macros y tareas vive en el frame del elemento que lo abrió,
no en variables compartidas.

| Bug | Antes | Ahora |
|---|---|---|
| Espacios entre elementos inline | `Rama:main` | `Rama: main` |
| Entidades HTML | `caf&eacute;`, `Hola&nbsp;mundo` | `café`, `Hola mundo` (`xml.HTMLEntity`) |
| Tareas completadas | `☐ Hecho` | `☑ Hecho` |
| Macro dentro de un panel | El panel perdía `[INFO: …]`: la macro interna pisaba el estado global | Encabezado conservado |
| Listas anidadas | `• Uno   • Uno.a` | `• Uno` / `   • Uno.a` |
| `<br>` sin cerrar | Se perdía todo lo que venía después | `xml.HTMLAutoClose` |
| `<ol start="3">` | `1. Tres` | `3. Tres` |
| XML mal formado | Se cortaba en silencio | Conserva lo leído y agrega un aviso visible de documento incompleto |

Concatenaciones dentro de `WriteString` reemplazadas por `writeLine`/`Fprintf`.
`bar40` medía 80 guiones: renombrada a `separator`.

## 5. Cómo verificar

```bash
cd ~/go/src/deploy-doc
export PATH="/usr/local/go/bin:$PATH"

# 1. Estático y tests — los tests corren en Linux y también en Windows
for os in linux windows darwin; do GOOS=$os go build -o /dev/null . || echo "FALLA $os"; done
go vet ./... && GOOS=windows go vet ./... && gofmt -l . && go test ./...
GOOS=windows GOARCH=amd64 go test ./cmd ./internal/backlog ./internal/config ./internal/atlassian
```

```powershell
# 2. Backlog — los dos repos del proyecto, guardando un archivo por repo
gtt backlog scan -p echo -o
#    Esperado: [1/2] backend y [2/2] frontend; rutas con "\";
#    %USERPROFILE%\.config\gtt\backlog\echo-backend.json y echo-frontend.json

# 3. Un solo repo y reglas de -o
gtt backlog scan -r frontend --since 30d
gtt backlog scan -o reporte.json          # con 2 repos: error que pide una carpeta

# 4. sin-test — agregar backlog.backend.class_globs al proyecto
gtt backlog scan -r backend               # sin la clave: "sin-test omitido" con el motivo

# 5. Sin credenciales — renombrar config.yaml temporalmente
gtt backlog scan --path C:\repos\mi-api   # funciona; gtt g / qa / fetch siguen pidiendo gtt init

# 6. fetch — una página con tildes, tareas marcadas y listas anidadas
gtt f -i APP-XXXX
```

**Verificado contra repos reales:** `operativo-api` (63 hallazgos, ~8 s) y
`echo-logistics` (35). Los hallazgos `sin-test` y los hotspots de mayor peso se
contrastaron a mano con `grep` sobre los tests y con `git log`.

**No verificado:**
- `--deps` contra un `composer audit` real: composer no estaba disponible en el
  entorno de prueba. El parseo de su salida está cubierto por tests, incluido el
  caso `"advisories": []`. Composer consulta el API de Packagist: por eso es
  opt-in.
- La ejecución en macOS: compila, pero no se corrió.

**Antes de probar un cambio:** usar `go run .`, nunca un binario compilado
suelto. Ejecutado desde fuera de la carpeta de instalación, `main.go` ofrece
autoinstalarse y una entrada vacía (EOF) cuenta como "sí": durante el desarrollo
de esta versión eso reemplazó un `gtt.exe` instalado por el build de desarrollo
y hubo que restaurar v1.3.0 desde el release, verificando el SHA-256.

## 6. Notas de compatibilidad

- **Comando nuevo, sin cambios en los existentes:** `generate`, `qa`, `fetch`,
  `project`, `init` y `update` mantienen flags y comportamiento.
- **Config:** la sección `backlog` es nueva y opcional. Sin ella funcionan todos
  los detectores menos `sin-test`, que aparece como omitido.
- **`config.yaml` con error de sintaxis:** ahora es un error explícito con la
  ruta y la línea, en lugar de "Corre: gtt init". Un archivo inexistente sigue
  sin ser error.
- **`gtt fetch`:** el `.txt` cambia donde antes salía mal (espacios, entidades,
  tareas, listas, paneles). Si un documento no se puede leer completo, el texto
  termina con un aviso visible en lugar de cortarse.
- **JSON de `backlog`:** formato nuevo, `version: 1`. `--json` imprime una lista;
  cada archivo de `-o` contiene un reporte. Las rutas van siempre con `/`.
