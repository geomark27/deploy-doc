# v1.3.0 — Preservación de contenido manual, correctivos y datos fuera del binario

**Fecha:** 2026-09-21
**Tipo:** Minor
**Versión anterior:** v1.2.10

---

## 1. Solicitud

Dos orígenes.

**Issue [#4](https://github.com/geomark27/deploy-doc/issues/4)** — Jordano-Alva, 2026-09-09:

> Ajustar la funcionalidad para que la sección "A Considerar" no se vea afectada, modificada ni sobrescrita cuando se realicen actualizaciones del documento en Confluence.
>
> La información registrada en esta sección debe mantenerse independiente de las actualizaciones realizadas sobre el contenido del documento en Confluence, garantizando que no se pierda ni se altere durante el proceso de actualización.

**Análisis del proyecto** solicitado el 2026-09-21, que identificó tres defectos con daño en producción y un conjunto de mejoras de robustez.

Se acordó un único tag para todo el conjunto en lugar de releases por fase.

---

## 2. Motivación

| Defecto | Daño real |
|---|---|
| `generate` reemplaza el body completo al actualizar | Pérdida garantizada: checkboxes marcados vuelven a TODO, tareas agregadas a mano desaparecen. Ocurre en **cada** actualización. |
| `addToPath` reescribía el PATH de usuario como `REG_SZ` | El PATH de Windows es `REG_EXPAND_SZ`. Al cambiar el tipo, entradas como `%USERPROFILE%\bin` quedan literales y dejan de resolver: rompe herramientas ajenas a `gtt` y es dificilísimo de diagnosticar. |
| Búsqueda por título con `&space-key=` en la API v2 | El parámetro no existe en v2 y se ignora en silencio: la búsqueda era global. Una página homónima en otro space podía ser encontrada y **sobrescrita**. |
| `HasDeployDocLink` devolvía `false` ante cualquier error | Un 401 o un timeout marcaba ✖ en "Documentación requerida" de un documento que se publica en Confluence como evidencia de QA. Falso negativo invisible. |

## 3. Diseño técnico

### 3.1 Preservación de la sección (issue #4)

`UpdatePage` no admite parches parciales: reemplaza el body. La única forma de
no perder contenido es leerlo antes y volverlo a emitir.

```
GetPageADF(id)                      → ADF previo + versión, en una sola llamada
  ExtractSection(adf, "A considerar") → nodos de primer nivel bajo el encabezado
    Build(DeployDoc{PreservedConsider: nodos})
      UpdatePage(...)
```

**Copiar, no fusionar.** `ExtractSection` devuelve los nodos sin inspeccionar
sus subárboles: no interpreta `taskList` ni estados de `taskItem`. La palabra
*"independiente"* del issue pide exactamente eso. Se descartó deliberadamente
un merge template + usuario, porque no puede distinguir "el usuario borró esta
tarea a propósito" de "esta tarea es nueva en la plantilla", y resucitaría
tareas eliminadas.

> **Consecuencia aceptada:** si la plantilla gana un paso obligatorio nuevo, los
> documentos existentes no lo reciben al actualizarse. Es el precio del
> preservado verbatim y es una decisión de proceso, no técnica.

**Fallar seguro.** El bug actual es silencioso, así que un fix que preserve
"cuando puede" y pise "cuando no puede" lo dejaría vivo en el peor caso:

| Situación | Comportamiento |
|---|---|
| Sección con contenido | Se preserva verbatim |
| No se pudo leer el ADF (red, 403) | **Aborta.** No se actualiza nada |
| Body en formato `storage` (editor viejo) | Warning + confirmación `[s/N]` |
| Encabezado ausente o sin nodos debajo | Warning + confirmación `[s/N]` |

El encabezado lo sigue emitiendo `Build`: es el ancla para encontrar la sección
en la actualización siguiente. Solo el cuerpo se arrastra.

**Fuera de alcance:** la celda "Épica" del `headerTable` tiene la misma causa
raíz y también se sobrescribe. El mecanismo ya está (`PreservedEpica` sería
análogo), pero el issue no la menciona y queda pendiente de confirmación.

### 3.2 PATH de Windows

Se lee el tipo real del valor y se reescribe con el mismo:
`SetExpandStringValue` si era `REG_EXPAND_SZ`, `SetStringValue` si no. La
detección de "ya está en el PATH" pasa de `strings.Contains` sobre el valor
completo a comparación por entrada normalizada (`canonPathEntry`): un substring
match también acierta con `...\Programs\gtt-old`.

### 3.3 Space en Confluence v2

`findPageByExactTitle(title, spaceKey)` resuelve la key a id numérico con
`ResolveSpaceID` y filtra con `space-id`. `FindPageByTitle`, `FindQAPage` y
`FindQAKanbanPage` eran el mismo cuerpo repetido tres veces: ahora delegan, así
el fix se aplicó una vez y no tres. Costo: un GET extra a `/spaces` por
búsqueda; se descartó cachear para no introducir estado compartido en el
cliente sin necesidad medida.

### 3.4 Errores no silenciados

`HasDeployDocLink` y `GetNovedadComment` devuelven el error. Se agregó
`QAIssue.DeployDocUnknown`: la columna se renderiza `?` en lugar de ✖, y la
consola emite un warning por tarea. Texto plano y no un emoji, para no depender
de qué set resuelve la instancia.

### 3.5 Escapado de JQL/CQL

`atlassian.quoteLiteral` — un único helper, porque JQL y CQL comparten reglas de
escape. Aplicado a `sprintName`, `module`, `accountID`, `issueKey`, `query`,
`spaceKey` y a los títulos interpolados. No es escalada de privilegios (el
usuario usa su propio token) pero un valor con comillas rompía la consulta o
alteraba el filtro en silencio.

### 3.6 Links de commit por host

`commitFileURL` distingue Bitbucket (`/commits/<hash>#chg-<path>`), GitHub
(`/commit/<hash>`) y GitLab (`/-/commit/<hash>`). Un host desconocido no genera
link: un enlace roto es peor que ninguno, porque el lector no puede distinguir
uno muerto de uno equivocado. GitHub va sin ancla por archivo — el ancla es un
digest de la ruta que no se puede reproducir desde aquí.

### 3.7 Constantes de instancia

`qaJiraProject`, `qaStatusIDs`, `fieldNovedades`, `fieldReprocesos` y
`fieldDevStatus` agrupados en un bloque `const` con comentario. **No** se movieron
a configuración: el comando `qa` es single-tenant por diseño y los ids de custom
field no tienen expresión portable. Se eligió el 80% barato — que sean
encontrables y estén documentados — sobre agregar seis claves de config y una
superficie de fallo sin beneficio actual.

### 3.8 `parseDevTaskKey`

Pasa de partir por `-` a `regexp` `[A-Z][A-Z0-9]*-\d+`, primera coincidencia.
Lo anterior devolvía `"1257 - ajuste"` con un sufijo y fallaba con guión largo.

### 3.9 Datos de la organización fuera del binario (P-008)

Tres cosas distintas, misma raíz:

1. **Nombres de personas** — tres nombres completos compilados en
   `qa_builder.go`. Se mueven a `qa_report` en `config.yaml`; ausentes
   renderizan `—`. Sin flag de override ni prompt en `init`: son tres valores
   estables que solo afectan al usuario QA.
2. **Nombres de repositorio por defecto** — `generate.go` caía en dos literales
   de un repositorio concreto cuando el proyecto no los definía. Ahora arrancan
   vacíos y `repoNameFromDir` los deriva del basename del directorio del clon,
   con warning. Un `strings` sobre el binario ya no revela repos internos.
3. **Ejemplos en textos de ayuda** — `(ej: devtyt)` en `root.go` e `init.go`, y
   un comentario en `builder.go`, neutralizados a `mi-organizacion`. P-007 cubre
   los strings tipo `token` como falso positivo, pero el nombre del workspace es
   topología: cae bajo P-001, no bajo P-007.

Documentado como patrón **P-008**.

### 3.10 Enlace remoto en Jira: error reportado

`CreateJiraRemoteLink` se llamaba con `_ =` en los dos caminos de `generate`.
No es fatal — el documento existe, que es el output del comando — pero el
silencio tiene un efecto en cadena que se lee como otro problema: `gtt qa`
verifica **ese mismo enlace** vía `HasDeployDocLink`, así que un fallo aquí
reaparece semanas después como una tarea marcada "sin documentación" en el
consolidado, con el documento publicado en Confluence todo el tiempo.

Se centraliza en `linkIssueToDoc`, que avisa con la acción concreta (agregar el
Web link a mano) y no aborta.

### 3.11 Checklist de despliegue configurable

`considerTable()` emitía `Ejecutar php artisan migrate`: un comando de un stack
concreto, compilado en un binario que corren otros equipos. Pasa a
`deploy_checklist`, con capas `proyecto > global > default genérico`. El default
ya no nombra ningún stack (`Ejecutar migraciones`).

`taskItem` pasa a generar `localId` posicional (`task-1`, `task-2`, …) en lugar
de derivarlo del texto: el texto ahora viene de configuración y puede contener
cualquier cosa, y el id solo necesita ser único dentro de la lista. Los
documentos existentes no se ven afectados — su sección se preserva verbatim y
nunca se reconstruye.

Solo aplica al **crear**. Al actualizar manda lo que el usuario editó.

### 3.12 Redacción del gate de `qa`

El mensaje decía `"acceso denegado: este comando es exclusivo para..."`, que se
lee como control de acceso. No lo es: `qa_email` sale del config del propio
usuario y se edita libremente. Es un guardarraíl contra publicar el consolidado
por accidente; la autorización real son los permisos de Atlassian. El mensaje
nuevo muestra ambas cuentas y dice cómo ajustarlo, sin insinuar que impide algo.

### 3.13 Tests

Primeros tests del proyecto. Solo funciones puras — **sin mock HTTP de
Atlassian**, que sería un harness de varios días a mantener al ritmo de la API.
49 tests en 6 paquetes, con target `make test` (no enganchado a `lint`: eso
cambia el gate de release y es decisión del equipo).

`ExtractSection` y `Build` se validaron además con un mutation test: revirtiendo
el fix, `TestBuildUsesPreservedSectionInsteadOfTemplate` falla.

## 5. Cómo verificar

```bash
cd ~/go/src/deploy-doc
export PATH="/usr/local/go/bin:$PATH"

# 1. Estático — los tres OS
for os in linux windows darwin; do GOOS=$os go build ./... || echo "FALLA $os"; done
go vet ./... && gofmt -l . && go test ./...

# 2. Issue #4 — el caso que reportó Jordano
gtt g -i APP-XXXX -b <hash>
#    En Confluence: marcar 2 checkboxes y agregar la tarea "Limpiar caché redis"
gtt g -i APP-XXXX -b <hash2> --dry-run   # inspeccionar el ADF fusionado
gtt g -i APP-XXXX -b <hash2>             # elegir [1] Actualizar
#    Esperado: checkboxes marcados + tarea agregada intactos,
#              tablas de archivos actualizadas

# 3. Fail-safe — contra una página creada a mano en el editor viejo
gtt g -i APP-YYYY -b <hash>              # debe warnear y pedir [s/N], no pisar

# 4. Space filter — crear dos páginas homónimas en spaces distintos
gtt g -i APP-XXXX -b <hash> --space PA   # solo debe encontrar la de PA

# 5. PATH de Windows — en VM o usuario de prueba, NO en la sesión principal
reg query "HKCU\Environment" /v PATH     # anotar el tipo ANTES
gtt
reg query "HKCU\Environment" /v PATH     # debe seguir siendo REG_EXPAND_SZ

# 6. QA tri-estado — con token revocado o baseURL inválido
gtt qa -s 17 -m DAI                      # "?" y warning, nunca ✖

# 7. qa_report — borrar la clave del config.yaml
gtt qa -s 17 -m DAI --dry-run            # Líder Técnico/PMO/QA deben salir "—"

# 8. deploy_checklist — agregar la clave y crear un documento nuevo
gtt g -i APP-ZZZZ -b <hash> --dry-run    # los pasos deben venir del YAML
#    Sin la clave: default genérico, sin mención de ningún stack

# 9. Enlace remoto — con un token sin permiso de escritura en Jira
gtt g -i APP-XXXX -b <hash>              # doc creado + warning, nunca error fatal
```

**No verificado:** la llamada real a
`GET /pages/{id}?body-format=atlas_doc_format`. La documentación de Atlassian la
respalda y sus ejemplos de respuesta incluyen `atlas_doc_format`, pero no se
probó contra la instancia. Si el campo llegara vacío, el comportamiento es el
fail-safe del punto 3 (warning + confirmación), no pérdida de datos.

## 6. Notas de compatibilidad

- **Config:** `qa_report` y `deploy_checklist` son nuevas y opcionales. Un
  config existente sigue funcionando; `qa` avisa y publica `—` hasta que se
  agregue `qa_report`, y `generate` usa el default genérico sin `deploy_checklist`.
- **Plantilla de documentos nuevos:** el paso `Ejecutar php artisan migrate`
  deja de emitirse por defecto. Si lo necesitan, va explícito en
  `deploy_checklist` — global o por proyecto.
- **Sin cambios en flags ni en nombres de comandos.**
- **Documentos existentes:** la primera actualización de un documento creado por
  una versión anterior preserva su sección normalmente — el encabezado
  "A considerar:" ya está ahí y es el ancla.
- **Windows:** un PATH que una versión anterior degradó a `REG_SZ` no se repara
  solo. Esta versión deja de causar el daño, pero un PATH ya afectado hay que
  corregirlo a mano (Variables de entorno → reescribir las entradas con `%VAR%`).
